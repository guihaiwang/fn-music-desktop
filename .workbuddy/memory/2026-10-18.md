## 修复 .null 拖拽区被 Scrollbar 挤掉
- 根因：Scrollbar 组件根 `.fnm-scrollbar{height:100%}` 在 flex 列里基值=整个 aside 高度，flex-shrink 后几乎吃掉全部空间，`.null`（data-tauri-drag-region）只剩 min-height 10px
- 修复：aside.vue 里用 `.aside-content .aside-scroll { height:auto; flex:0 1 auto; min-height:0 }` 覆盖（双类提高优先级，父 scoped 可命中子组件根）
  - 列表短：滚动区收缩到内容高度，剩余空白全部归 .null → 可拖拽窗口
  - 列表长：flex 自动把滚动区压成视口（可滚动），.null 保持 10px 细条
- agent-browser 实测：3 条歌单时 sb 高 400=内容高、.null 高 95px 可拖拽；20 条时 sb 485、scrollTop 可到 493、thumb 比例正常
- 教训：init-script 是启动时绑定的，换 mock 必须 agent-browser close 后重新 open（同 URL open 不会重挂 init 脚本）
- 截图：/tmp/fnm-null-short.png、/tmp/fnm-null-long.png

## 原版错误码→文案机制（查证）
- 是前端硬编码的「错误码→多语言文案」Map，不在 locales JSON、不透传后端 msg
- chunk 5e884898…：枚举 J（Unknown=100001…PlaylistNameExists=160001、PlaylistHitMaxCount=160002…）；四语言 Map 挂 ob={zh-CN,en-US,ja-JP,de-DE}，zh-CN 里 160001→「歌单名称已存在」
- 解析 ub({code,defaultMessage,locale})：ob[locale].get(code) ?? ob['zh-CN'].get(code)（zh 兜底）?? defaultMessage ?? ab[locale]（"操作失败"）
- 后端 msg（如 "playlist name already exists"）进 ApiError.backendMessage，仅当 code 不在映射表时才作为文案展示；成功码 Zy=[0,200]
- 我方应用可照抄：http.ts 增加 code→zh-CN 文案映射，e.message 优先取映射

## "菜单右侧 1px 竖线"之谜 = 自绘滑块
- 用户截图：首个菜单行右侧一条 ~1px 竖线，且"刷新时在哪个菜单就在哪个菜单上"；用户确认与 scrollbar 有关
- 真相：是 Scrollbar 自绘滑块（thumb）。刷新后浏览器还原 wrap 滚动位置 → 滑块停在轨道顶部（正对第一个菜单行）；列表长→滑块短、低透明度→看着像细线；旧逻辑"悬停容器即显示"让它频繁冒出来
- 轨道几何佐证：bar rect [168-174, 80-561]，顶部 80 正是首个菜单行
- 修复（Scrollbar.vue，对齐 macOS 原生滚动条）：去掉 `.fnm-scrollbar:hover>bar` 显示规则，改为滚动时点亮——handleScroll 置 is-scrolling（class + state），停止 700ms 淡出（scrollHideTimer，卸载清理）；拖动/always 规则不变
- 实测：悬停不滚动 opacity 0；滚动中 opacity 1 + is-scrolling；停止 1.2s 后 opacity 0
